# Dataset card

The research package evaluates two existing, versioned case sets. It does not copy them: each is referenced by path and SHA-256, so there is one source of truth.

The schema is `research/dataset/schema.json`. `research/scripts/validate_dataset.py` checks it, together with what JSON Schema cannot: unique ids, existing events and fixtures, the recorded hash, and the label vocabulary. The validator fails closed and never repairs.

**Completeness state.** The basis of every admitted completeness declaration is recorded per pair, as `basis` in `research/results/retro/evaluation.json`. Results are stratified by it (`by_completeness_basis`).

**Scope.**
- In-scope candidates (102 pairs) are real references, at a commit, to the affected object.
- Neighbours (65 pairs) follow four templates, n1–n4 (`DESIGN.md` §5):
  - the same name in another namespace or registry;
  - a same-named package of another project;
  - a version just outside the boundary;
  - the new canonical location after a move.

The two undeterminable pairs are EOL cases whose version cannot be read from the reference.

**Events and their provenance.**
- Each event has a fixture `evaluation/retrospective/events/<ID>/event.json` and a `SOURCES.md` that lists:
  - every primary URL;
  - its Wayback Machine snapshot;
  - the fetch time;
  - a "Representation" note on what OSV/OpenVEX could and could not express.
- Each case's `label_source` names that file plus the dependent repository, commit and file in which the reference was found.
- Events are listed in `SHORTLIST.md`: 33 researched, 27 included, 6 rejected with reasons.

## 3. Known limitations of the sample

- **Purposive, not random.** Events were chosen to cover classes under quotas (`SHORTLIST.md`). They are famous, well-documented incidents. Nothing here estimates how often such events happen, or how a randomly drawn dependency fares.
- **Survivorship.** References were found in repositories that still exist and are searchable.
- **Small.** 27 events. The registered prospective study needs at least 60 events at risk for H1 (REGISTRATION.md).
- **Ecosystems.** npm, Go and container images only.
- **Two taxonomies.** The development set says `lifecycle`, `archival` and `breaking-change` where the retrospective set says `eol` and others. Per-class results do not compare across the sets.
- **Labels are the developer's** (§4).

## 5. Redistribution and personal data

- **Events.** Events are public facts. Fixtures quote short excerpts of public announcements, with links and archive snapshots.
- **Dependent repository names.** `label_source` and the dependency references name public GitHub repositories as `owner/repo@commit`. Some owners are individual accounts. These are public identifiers, used only to locate a reference, but they identify people. Before archiving the dataset publicly with a DOI, the authors should decide whether to keep them, or to replace owner names with stable hashes plus a separately held key. **Decision needed (Principle 10).**
- **Licence.** No separate dataset licence is declared. The repository is Apache-2.0. Quoted announcement excerpts remain their publishers' material.

## 6. Versioning rule

A changed label, case, event fixture or reference is a **new version**: new file, new hash. Frozen files are never edited in place. `.gitattributes` keeps their bytes (`-text`), so the hash survives a Windows checkout.
