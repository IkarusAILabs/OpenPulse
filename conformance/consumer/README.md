# OpenPulse evidence consumer

Validate and read OpenPulse evidence contracts **without OpenPulse**. A consumer of OpenPulse's evidence (a CI step, a dashboard, a policy engine, an auditor) can install this package alone and check that a document is a well-formed contract of the version it claims, using only the published JSON Schemas.

It imports nothing from OpenPulse, and its one runtime dependency is [`jsonschema`](https://pypi.org/project/jsonschema/) (Python 3.11+).

## Install

From this directory, with every dependency hash-checked:

```bash
python -m pip install --require-hashes -r requirements.lock
```

```bash
python -m pip install --no-deps .
```

## Use

```bash
openpulse-consumer check contracts.jsonl
```

```bash
openpulse-consumer versions
```

`check` reads JSONL (one contract per line, as `openpulse attest --output` writes them) and prints one line per document, then a count:

- **Exit 0:** every document is valid against the schema of the version it declares.
- **Exit 1:** any document is not, with each problem's JSON path. A line that is not JSON, a version with no published schema (`2.9.0`), a missing required field and a field a closed schema does not allow all fail.
- **Exit 2:** a file cannot be read, or holds no contract. An empty file is never a pass.

From Python:

```python
from openpulse_consumer import check, read_jsonl

for line, doc in read_jsonl("contracts.jsonl"):
    result = check(doc)
    print(line, result.version, result.valid, result.errors)
```

## What it checks, and what it does not yet

- **Now (v0.19.0 P1):** each document against exactly the schema its `contract_version` names. Contracts 1.0.0 to 2.4.0 are bundled. `format` keywords are annotations, as JSON Schema 2020-12 defines them, so the result never depends on optional format packages.
- **Next (P2–P5):** exact-version rules (`provenance.contract_version` must match), content-hash verification for 1.x and 2.x, a summary that keeps every outcome apart (NOT_AFFECTED, RELATED, UNKNOWN, PARTIAL coverage, MISSING_EVIDENCE, NOT_PERFORMED) and never folds an incomplete one into a pass, and a corpus of documents from every released contract version.

## For OpenPulse maintainers

- The schemas under `openpulse_consumer/schemas/` are copies of `schemas/evidence-contract/`. After adding or changing one, run `python conformance/consumer/sync_schemas.py`; OpenPulse's tests fail until you do.
- `requirements.lock` is generated by `scripts/compile_locks.py`, with the same pins as OpenPulse's own locks.
- `tests/` runs with `unittest` alone. CI installs the package outside the checkout and runs the tests and `check` on fresh `openpulse attest` output.
