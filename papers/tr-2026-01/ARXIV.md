The source bundle and the metadata below are ready. Submitting needs the
author's arXiv account, so the steps marked **Author** are yours.

## 1. Get the bundle

The `paper` workflow builds it on every pull request that touches
`papers/`, and on demand:

```bash
gh workflow run paper.yml --repo IkarusAILabs/OpenPulse --ref main
gh run download --repo IkarusAILabs/OpenPulse --name tr-2026-01-arxiv
```

`tr-2026-01-arxiv.tar.gz` contains `main.tex`, with its full-line comments
removed because arXiv publishes the source, and the generated `main.bbl`,
because arXiv does not run BibTeX. The workflow recompiles that bundle
with BibTeX disabled and fails on any undefined reference or citation, so
a green run means arXiv can build it. `main.pdf` next to it is that
rebuild; check it before uploading.

**Abstract** (1,698 characters; arXiv allows 1,920. The PDF keeps its
full abstract.)

> Dependency decisions rely on vulnerability advisories and lifecycle catalogues, yet some upstream changes that alter a dependency's trust, maintenance or availability appear in neither: a repository relocated or archived, or versioned images withdrawn from a namespace still in use. AI coding agents now make such decisions too. The central risk is a false clear: reporting a dependency as not affected when it is. We present OpenPulse, an open-source instrument that collects, qualifies and applies upstream change evidence to declared inventories. Our contribution is a testable applicability model: typed scope elements over heterogeneous identities, completeness with a recorded basis, and a negative only when a complete scope has every element decisively excluded, with a short conditional soundness lemma. An audit against the model found sixteen defects, thirteen of which could produce or display false clears; fifteen are fixed. A specification-derived oracle agrees with the implementation on 100,000 random cases and a 6,195-case matrix, apart from one documented label, and catches all 22 re-injected mutants. An exploratory retrospective study of 27 historical changes, selected under quotas, and 167 references labelled by the developer describes those events, not a deployed rate: of 103 affected references, a naive reading falsely cleared 35 in 10 events and the event-scope engine none, through typed membership and identity rather than the completeness condition. The engine warned on 64, left 27 unresolved and missed 12 silently. The security claim is conditional and covers one decision path. A prospective, independently labelled evaluation is specified as an open protocol.

## 3. Before submitting (Author)

1. **The external reviews.** The AI-assistance section says the AI
   assistants drafted "the responses to external reviews". Readers, and
   later the journal, will ask who wrote those reviews. If any review was
   generated by a language model, say so in that section, and don't call
   them peer review. The removed source comment on line 3 of `main.tex`
   recorded this as an open item.
2. **Endorsement.** A first submission to cs.SE needs an endorsement from
   an established cs.SE author. arXiv tells you after you start the
   submission whether you need one.
3. **The author's name.** arXiv metadata accepts Unicode, so "Kış" is
   preferable to "KIS". Use the same form in every later paper so the
   author records merge.

## 4. After posting (Author)

Add the arXiv identifier to `CITATION.cff` (`identifiers`), to the README
